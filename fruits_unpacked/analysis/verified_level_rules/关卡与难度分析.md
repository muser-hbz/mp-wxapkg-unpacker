**一局内部也在逐段增难**

`typeArr`、`countArr` 是按阶段组织的二维数组，分别存水果ID及对应数量。普通模式多为三个阶段。原版普通下落关的种类池上限依次为：

```text
第1段：6种
第2段：14种
第3段：22 + min(11, floor(L/10)) 种
```

累计供给数量的参考点是目标量的10%、50%、100%。前段种类少，后段种类多；每次以2个或偶数倍加入同类水果，再补齐阶段目标并洗牌。参考比例不是严格的分段占比：先遍历类型就可能越过阈值，最后一次加入也可能使实际数量略超目标。

常规分支经 `getMaxType` 限制：皮肤0最多33种，其他皮肤最多28种。尾数6的特殊排列分支另行计算，不走这个截断。尾数8原代码的首次遍历条件写为“目标数 < 已生成数”，初始不成立，实际依靠随机成对补齐；因此不能说所有模式都会先保证每种水果至少出现一对。[种类上限](/Users/bingzhou/Projects/mp-wxapkg-unpacker/fruits_unpacked/analysis/verified_level_rules/source_excerpts.txt:239)

有成对的供给量，不代表棋盘一定能在有限槽位下无道具通关；生成路径还涉及隐藏、绳索、落点及物理接触顺序。

**水果数量曲线：以原版普通下落关为例**

以下只适用 `lv2_3_5Config` 分支。设N为供给目标，C和D为阶段上限；尾数2时 `C=228,D=248`，其他适用关卡 `C=238,D=268`：

```text
L < 10：    N = 100 + 10×(L−3)
11≤L<30：   N = 172 + 2×(L−11)
30<L<100：  N = min(C, 210 + 2×floor((L−30)/5))
L≥100：     N = min(D, C + 2×floor((L−100)/5))
```

例如原版3关目标100、5关120、11关172、13关176、31关210。10/30等尾数0关走黑洞分支，不适用上述公式。左右移动、问号、连接关各有自己的基数、增幅、间隔、上限；全部参数已保存在JSON中。

尾数6是重要例外：`lv6Config`只控制问号数量，地图生成器重新计算供给量。6关目标130、16关182、26关202、36关212；100关以后使用 `min(268,238+2×floor((L−100)/10))`。这段数量逻辑没有读取原版/简单/困难的数量参数，因此三档主要在问号数上产生差异。前约1/3使用1～11号水果，后段使用1～`22+min(11,floor(L/10))`号，成对生成并分别洗牌。[实际地图生成](/Users/bingzhou/Projects/mp-wxapkg-unpacker/fruits_unpacked/analysis/verified_level_rules/source_excerpts.txt:245)

**障碍和物理规则**

- 尾数2的原版木桩数随十位阶段交替为6或2，`scaleExp=0.9`。并非“12关以后每关都有树桩”。
- 尾数1用 `theme=floor(max(1,L−1)/10)%4` 切换机制。theme2的21/61/101…关有冰冻，原版数量 `min(15,7+floor(L/40))`；theme3的31/71/111…关有障碍，数量 `min(10,5+floor(L/40))`。theme1的11/51/91…关播放闪电，并随机选择约 `floor(水果数/13)` 个水果（索引至少20、Y至少300）自动落下，增加处理压力；不是清除奖励。
- 问号水果是暂时隐藏种类的盒子，落入判定区域或接触地板后揭示；提高的是信息判断难度。
- 冰冻只从数组索引30及之后选择，要求 `y≤顶部−400`。解冻计数为 `floor(abs(y−stopDownY)/(顶部−stopDownY)×水果数×0.5)+RandomInt(0,5)`。这是实际表达式，并无单独的 `min(N/2,...)` 硬截断。消除回调对冰冻计数递减，有0.01秒去重锁；冰冻水果不可直接点击。[冰冻代码](/Users/bingzhou/Projects/mp-wxapkg-unpacker/fruits_unpacked/analysis/verified_level_rules/source_excerpts.txt:688)
- 障碍物Y方向等分布置，X在[-208,208]随机，改变落下路径。连接/绳索限制水果脱离及配对顺序。
- 黑洞仅在尾数0关。令 `q=(L/10)%10`：q=1时2洞，q=2～7时3洞，其余4洞。所以10关2洞、20～70关3洞、80～100关4洞、110关又是2洞。
- 原版黑洞隐藏供给目标为 `A=min(14+floor(L/10),34)+4×(洞数−2)`。不是旧文档所写的均匀随机14～34。随后从水果池分配、成对补齐、排序并分洞；随机的是类型与分配，填充粒度也可能使目标与实际数量不同。洞的位置按十位周期选择固定坐标，最终乘0.695。[黑洞分支](/Users/bingzhou/Projects/mp-wxapkg-unpacker/fruits_unpacked/analysis/verified_level_rules/source_excerpts.txt:30)
- 实际 `FruitConfig.shuffleArray` 是从末尾向前的 Fisher–Yates 洗牌，随机交换区间为[0,当前索引]。游戏包里保留的“随机互换N次，非均匀”说明与当前实现不同，应以代码为准。[洗牌实现](/Users/bingzhou/Projects/mp-wxapkg-unpacker/fruits_unpacked/analysis/verified_level_rules/source_excerpts.txt:412)

**失败重试和广告是否降难度**

已确认生效的路径：

1. 失败写入持久化标志 `undergoLvnew=true`。每次新开局，当展示关卡 `fakeGame_level>1` 且标志为真，地图初始化完成后安排弹窗；两种奖励由 `Math.random()>0.5?1:0` 选择，各约50%。只需一次失败，无连败次数门槛；领取或关闭不消费标志，直到通关才清除，因此退出重进或继续重开仍可触发。
2. 激励成功且游戏仍在进行时执行救援：前者拆除当前局剩余槽位墙，每堵容量+1，通常3槽变5槽；重开创建新游戏实例后恢复3槽，同局复活保留。后者调用 `btnRemoveFun(6)`，目标最多6对：槽空时随机遍历普通可作为起点的水果寻找配对；槽非空时从槽内末尾往前找配对，不足6对不会再转向普通起点池补满，随后额外尝试至多1对“槽内＋洞内”配对。配对对象可能来自普通/绳索水果、洞口当前水果、冰冻或问号水果，并执行相应解绑/解冻。
3. 消除进度超过50%、槽位刚好占满、仍有可拆墙、本局尚未弹过时，还会出现“解锁一个槽位”的广告入口。
4. 重开重新生成同一关，随机布局会变化；胜利清除失败标记。`challengeCount`用于失败次数显示/存档，胜利清零，没有找到它传入数量、种类公式或难度分组切换的调用。

关闭特殊道具弹窗只关闭界面，不发奖励，不清除失败标志。视频未完整观看或加载失败不发奖励，失败回调不会关闭这个弹窗。此入口允许微信分享替代：当 `dayShareNowNum < dayShareNum` 且分享回调成功时也会发奖；测试/免广告模式可直接模拟成功。构造里的25秒计时字段没有对应生效流程，不能解释成25秒冷却。该开局规则与进度50%触发的单槽入口相互独立。

这属于“根据失败/局内压力提供道具帮助”。不能据此说“连败后自动少发水果”或“看广告后下一关自动变简单”。[失败标记](/Users/bingzhou/Projects/mp-wxapkg-unpacker/fruits_unpacked/analysis/verified_level_rules/source_excerpts.txt:447)、[下次开局](/Users/bingzhou/Projects/mp-wxapkg-unpacker/fruits_unpacked/analysis/verified_level_rules/source_excerpts.txt:708)、[广告发奖](/Users/bingzhou/Projects/mp-wxapkg-unpacker/fruits_unpacked/analysis/verified_level_rules/source_excerpts.txt:784)

另有一套潜在设计：`ScoreLvMgr.addDeathScore/addAdScore` 每次加1，`getReduceFruitTypeCount` 返回 `min(floor(score/10),5)`。但全包解码后这三个名字只找到方法定义，没有调用；实际 `getMaxType` 没有读取该减值。因此只能记为“存在但未见接入”，不能列入当前已生效规则。[积分代码](/Users/bingzhou/Projects/mp-wxapkg-unpacker/fruits_unpacked/analysis/verified_level_rules/source_excerpts.txt:470)

**通关压力的直接来源**

同ID水果满足接触/区域条件时两两消除。默认槽位容量3，拆两面墙可到5；容量失败条件是 `槽内数量>slotsNum`，因此默认第4个未消除水果才超容量。另有近似死局判断：没有黑洞时，槽满且槽内无同ID、槽外无可配对候选，或者剩余水果全已入槽并被点过，会判失败。剩余水果数≤0即胜利。隐藏种类、后段种类池扩大、绳索和物理路径，都会放大有限槽位带来的压力。[配对](/Users/bingzhou/Projects/mp-wxapkg-unpacker/fruits_unpacked/analysis/verified_level_rules/source_excerpts.txt:488)、[失败](/Users/bingzhou/Projects/mp-wxapkg-unpacker/fruits_unpacked/analysis/verified_level_rules/source_excerpts.txt:523)、[胜利](/Users/bingzhou/Projects/mp-wxapkg-unpacker/fruits_unpacked/analysis/verified_level_rules/source_excerpts.txt:585)

分析边界：这是本地包的行为证据，不是在线通关率测量。未模拟完整物理棋盘，未确认真实实验分组、广告完成状态或热更新后的代码。不能从这些配置推算一个可靠的“每关通关率”。
