# 鸽子小游戏关卡规则与配置

普通关卡先读取固定的叠板布局，再按关卡参数随机生成螺丝颜色。同一配置关号使用相同的板型、坐标、角度和分层，重进时会重新配色。包内有 **310 套主线布局、10 套挑战布局**，以及入口默认关闭的 **80 条透明模式参数**。主线累计进度超过 310 后，布局和参数按 50～310 循环，玩家关号继续增长。

## 关卡资源和加载顺序

| 模式 | 布局资源 | 数值配置 | 每局或每段规模 |
| --- | --- | --- | --- |
| 主线 1～100 | `totalLv1`，100 套，9,744 块板 | `levelConfig`、`levelDiffConfig` | 3～122 块板，3～28 层，实际生成 6～240 颗螺丝 |
| 主线 101～310 | `totalLv2`，210 套，19,732 块板 | 同一套主线数值表 | 81～104 块板，21～24 层，200～230 颗螺丝 |
| 每日挑战 | `totalChallLv`，10 套，1,178 块板 | `levelConfig_Challenge`、`levelDiffConfig_Challenge` | 96～131 块板，25～29 层，250～310 颗螺丝 |
| 透明模式 | 当前总关卡配置入口只为主线、挑战取布局 | `levelConfig_Transparent`、`levelDiffConfig_Transparent` | 80 条参数，120～240 颗螺丝 |

`Game.scene` 序列化的 `GameMain.lvLoadType` 为 `2`，实际走 `LvCreator.createLvByTotalLvCfg`。`GameUtil.createLvByDiffCfg` 在这份包中返回空数组。`totalLv1` 和 `totalChallLv` 随 Loading 场景加载。首次启动时，主线关号大于 100 会等待 `LvData/json/totalLv2` 的加载回调，较早进关则在关卡初始化后预加载。取主线布局时，101～310 对应 `totalLv2` 的下标 0～209。分包数据尚未注册时，超过 100 的配置关号会取 `totalLv1` 的最后一条布局。 [Game 场景序列化](../dec/assets/main/import/0a/0a0631e5e.a7053.json) · [LvData 资源索引](../dec/subpackages/LvData/config.7cc1a.json) · [进关代码](../dec/game.js#L34)

Loading 先注册包内参数。微信等平台随后可独立更新普通参数、普通难度、挑战参数和挑战难度四张表，每张请求成功后覆盖对应内置表，失败时继续使用包内数据。本文关卡数值来自当前解包文件。 [Loading 场景资源](../dec/assets/start-scene/import/0a/0ad82a5fe.648c5.json) · [加载代码](../dec/game.js#L34)

## 布局字段和板型

| 字段 | 含义 |
| --- | --- |
| `name` | 字符串形式的布局关号。主线是 `1`～`310`，挑战是 `1`～`10` |
| `plates` | 按构建顺序存放的板数组，螺丝也按此顺序依次取用 |
| `plates[].id` | `MianBdl/Prefab/plateNew/<id>`，共有 43 个板型 |
| `plates[].x`、`y` | 板在所在层的本地位置。总关卡配置入口直接使用这组坐标 |
| `plates[].a` | 板的旋转角度，单位为度 |
| `plates[].g` | 从 1 起的层号，用于分层、遮挡和物理分组 |

每种板有 1～6 个孔，`GameUtil.getPlateHoleCount` 从 `GameCfg.plateHoleConfig` 按板型取孔数。例如 1、3、7、10、21 号板各有 1 孔，27 号板有 2 孔，43 号板有 6 孔。板的碰撞组按 `G1`～`G29` 映射，包内主线最高到 28 层，挑战最高到 29 层。 [板型资源索引](../dec/subpackages/MianBdl/config.a7b94.json) · [后段布局资产](../dec/subpackages/LvData/import/22/226f8b27-f8e9-4e46-95bb-a7cd4285ba8b.8a88e.json) · [板组件和孔数表](../dec/game.js#L34)

逐关累加孔位后，**主线 2～310 和挑战 1～10 全部与配置 `screw` 一致**。主线第 1 关表值为 4，布局为 3 块双孔板，`initScrewArray` 对该关直接返回 6 颗指定颜色的螺丝。 [关卡构建代码](../dec/game.js#L34)

除主线第 1 关外，`LvCreator.initScrewArray` 先打乱 13 个基础色。每段从这份色表取前 `type` 个候选。前几段用相邻累计百分比之差乘以 `screw` 向下取整，优先给候选色逐一分配一枚，再随机填到段配额。末段先补齐此前出现奇数枚的颜色，再按同色双枚填满剩余配额。各段内部打乱，拼接后整体反转，按每块板的孔数切片。随机实现使用 `Math.random`。 [配色代码](../dec/game.js#L34)

以 101 关为例，难度 6 的八段生成 `21 × 7 + 63` 颗螺丝。候选色数从 7 增至 12，最后一段处理全局配对需要的奇偶补齐。

### 神秘和冰封螺丝

- `mystery` 是普通模式的目标数量。包内从 101 关开始有配置，共 60 关，目标值分别为 3、4、5。候选来自按布局顺序展开的后 80% 孔位，已选孔所在层之间至少差 3 层。首个启用关优先尝试把最后一颗标为神秘，并调整邻位以保留同色配对。随机遍历受间距约束，实际标记数可能小于目标。拆出时立即显示原色，继续按原色配对。
- `iceCount` 和 `iceUnlock` 出现在普通 8～12 关。包内冰封开关为 `false`，`iceCount` 用于求配置起始关，运行逻辑中未找到读取 `iceUnlock` 的入口。 [特殊螺丝代码](../dec/game.js#L34)

## 对局规则

- **选钉和遮挡。** 点中螺丝圆形区域时从前向后找板。前方不同碰撞组的板与螺丝相交会挡住这次点击，同组板不挡。拆出后螺丝进入底部物理槽。板上剩少于两枚时启用该碰撞组的刚体，板无钉且落到底部后移除。
- **配对和通关。** 两枚同色螺丝还要满足接触与落底支撑条件。空中擦碰会延迟复查。进度按已消除螺丝数除以开局实际螺丝数计算，达到 100% 触发通关。板上无钉、弹出节点不超过两枚时另有三秒兜底，回调要求当前未结束且未满槽。
- **容量和失败。** 底槽默认 4 位，两次解锁各加 1，解满为 6。槽满，或板上无钉且槽内剩三枚以上并已全部落底，会进入复活或失败。计时用于上报，通关判定没有倒计时。
- **道具和复活。** 移除最多挑两对，优先用底槽候选。重排调整板上螺丝的颜色、生成段和神秘标志，优先让底槽前两枚的颜色获得配对机会。复活从底槽位置最高的螺丝开始移回新板，目标数量为 3 加上超出槽容量的数量，最多取完槽内螺丝，然后免费重排一次。
- **关号和奖励。** 主线获胜把玩家关号加一，失败累计失败次数。普通图鉴按赢下的关号推进，共 93 条，门槛最高到 900。挑战图鉴按累计挑战胜场推进，共 30 条。 [判定、道具及图鉴代码](../dec/game.js#L34)

## 每日挑战

主线通关第 10 关后开放。默认每天 1 次免费和 2 次广告开局机会，当天挑战成功后入口会阻止再次开局。跨日从 1～5 号首段中排除上一次首段后随机选取。首段胜利自动进同一编号 `+5` 的第二段，第二段胜利才记录当天成功及一次挑战胜场。两段共享一次复活和各一次移除、重排额度。 [每日挑战代码](../dec/game.js#L34)

## 本地查询

在仓库根目录运行以下命令。脚本输出 JSON，可查看模式汇总、整张模式配置或单条配置。单条结果同时给出难度档、分段预算，以及板数、层数和按板型计算的孔数。挑战编号是配置编号，主线循环关按映射后的配置编号查询。 [查询脚本](./inspect-levels.js)

```sh
node pigeon_unpacked/analysis/inspect-levels.js
node pigeon_unpacked/analysis/inspect-levels.js normal
node pigeon_unpacked/analysis/inspect-levels.js normal 101
node pigeon_unpacked/analysis/inspect-levels.js challenge 6
node pigeon_unpacked/analysis/inspect-levels.js transparent 80
```

## 复核位置和验证范围

`Game.scene` 的加载模式值位于 `[5][7][0][15][4][1][1]`，`totalLv2` 数组位于其导入文件的 `[5][0][2]`。Loading 场景的 JsonAsset 名称和数据在 packed 记录 `[5][i][0][0]` 的第 1、2 项。主线参数、难度和布局的 `i` 分别为 `27`、`41`、`31`，挑战为 `32`、`33`、`43`，透明参数和难度为 `1`、`44`。 [Game 场景](../dec/assets/main/import/0a/0a0631e5e.a7053.json) · [Loading 场景](../dec/assets/start-scene/import/0a/0ad82a5fe.648c5.json) · [LvData 导入文件](../dec/subpackages/LvData/import/22/226f8b27-f8e9-4e46-95bb-a7cd4285ba8b.8a88e.json)

本地核对覆盖 400 条关卡参数和 320 套布局。用 Node 执行包内原始配色函数抽样 16,000 次，生成数全部等于布局孔数，每色数量均为偶数。另抽样 3,000 次验证神秘螺丝的候选位置、层间距和数量上限。对局规则依据本地代码，微信线上表值和实机物理表现需要另行核对。
